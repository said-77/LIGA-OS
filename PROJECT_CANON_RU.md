# Архитектурный и продуктовый канон LIGA OS (PROJECT_CANON_RU.md)

## 1. Назначение и позиционирование
LIGA OS — это узкоспециализированная операционная среда для ведущего мастера элитной сантехники и отопления в Ташкенте (Улугбек Хакимов).
Продукт предназначен для работы на реальных премиальных объектах (ЖК Mirabad Avenue, Nest One, Tashkent City, закрытые коттеджные поселки).

---

## 2. 5 Инженерных догм Лиги Мастеров
1. **Гидравлическое испытание 16 бар (24 часа):**
   Рабочее давление в Ташкенте — 3–4 бара. Ночные гидроудары достигают 8–10 бар. Мы опрессовываем систему давлением 16.0 бар в течение 24 часов. Без этого ни один объект не сдается.
2. **Честность паспорта (No Fake Guarantee):**
   Паспорт объекта остается строгим **ЧЕРНОВИКОМ** (`DRAFT`), пока мастер физически не внесет дату/время старта и окончания, проверенное давление не менее 16 бар, фото манометра с отметкой 16 бар и личное инженерное заключение.
3. **Защита конфиденциальности мастера (Режим показа клиенту):**
   При показе экрана смартфона заказчику внутренние начисления бригаде, оптовые цены закупки с базаров Джами/Урикзор и бонусы дизайнерам физически исключаются из модели представления (`getClientViewModel`).
4. **Автономность ядра (Offline Core):**
   Ядро LIGA OS работает офлайн (база объектов IndexedDB, расчет сметы, чек-листы технадзора, паспорт); голосовая диктовка, внешние ссылки и отправка расписок в мессенджеры требуют сеть.
5. **Премиальная эстетика Glassmorphism:**
   Две контрастные темы: Dark Titanium (глубокий графит и золото для вечерней работы) и Light Ceramic (высококонтрастный текст `#090e17` для работы под ярким ташкентским солнцем).

## 3. Архитектурный канон
- **Frontend Core:** Vanilla HTML5, CSS Variables, ES6+ Modules. Никаких сторонних тяжелых библиотек (React, Vue, Webpack).
- **Database:** IndexedDB (база `liga_master_db`, хранилища: `sites`, `materials`, `checklists`, `finances`, `passports`).
- **Data Integrity:** Резервные копии JSON содержат сигнатуру `appName="LIGA OS"`, схему `schemaVersion >= 1`, 5 обязательных секций и проверку внешних ключей `siteId`. При сбое восстановления текущая база автоматически откатывается к исходному состоянию.
- **Client Security:** Изоляция приватных данных через специализированную View-Model (`getClientViewModel`), предотвращающую попадание коммерческой тайны мастера в DOM заказчика.
