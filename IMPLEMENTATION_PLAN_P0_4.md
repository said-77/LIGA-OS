# План реализации P0-4: Надежное локальное резервное копирование и восстановление (Full JSON Backup & Restore)

## 1. Описание задачи и архитектурный контекст
Ведущий инженер Улугбек Хакимов работает полностью автономно на объектах в Ташкенте (включая монолитные подвалы и новостройки без интернета).
Вся база данных (объекты, сметы, чеки с базаров, фото манометров опрессовки и узлов) хранится локально в IndexedDB на его смартфоне.

**Критическая потребность мастера**:
1. Иметь возможность в 1 клик выгрузить полную резервную копию всех данных прямо на объекте и отправить её себе в Telegram («Избранное»), WhatsApp или сохранить в память смартфона через системное меню «Поделиться» (`navigator.share`).
2. Иметь возможность при смене смартфона, случайной очистке кэша браузера или сбое гарантированно восстановить всю рабочую базу из файла `.json`.
3. Защита от повреждения данных: перед заменой данных приложение обязано строго валидировать схему файла, показывать мастеру понятную карточку (дата создания, количество объектов, чеков, тарифов) и требовать явного подтверждения.

## 2. Предлагаемые изменения по компонентам

### 2.1. Модуль базы данных (`js/db.js`)
#### [MODIFY] [db.js](file:///h:/PROEKTY/МОЁ_GPT_ПРОСТРАНСТВО/LIGA-M_OSIM/LIGA-OSIM/LIGA_OSIM/js/db.js)
1. **Метод `createBackupPayload()`**:
   - Сбор полного снимка данных:
     - `appName`: `'LIGA OS'`
     - `schemaVersion`: 1
     - `dbVersion`: `DB_VERSION`
     - `exportDate`: ISO timestamp
     - `sites`: массив объектов
     - `materials`: массив материалов и чеков
     - `checklists`: массив пунктов технадзора
     - `passports`: массив паспортов
     - `tariffSettings`: текущие тарифы мастера из `localStorage`
   - Возврат сериализуемого объекта и форматированной строки.
2. **Метод `exportBackupFile()`**:
   - Создание файла `liga_backup_YYYY-MM-DD.json`.
   - Проверка поддержки системного меню смартфона `navigator.share` с поддержкой передачи файлов (`navigator.canShare({ files: [file] })`).
   - При поддержке: вызов `navigator.share({ files: [file], title: 'Резервная копия LIGA OS', text: 'Полная резервная копия базы объектов LIGA OS' })`.
   - При отсутствии поддержки или отмене пользователем: автоматическое безопасное скачивание файла через `<a download>`.
3. **Строгий валидатор схемы `validateBackup(data)`**:
   - Проверка типа (объект, не null, не массив).
   - Проверка сигнатуры приложения (`appName === 'LIGA OS'` или наличие корректной структуры `sites`).
   - Проверка целостности ключевых сущностей: `sites` обязан быть массивом, где каждый элемент имеет `name` и `id`.
   - Проверка массивов `materials` и `checklists`.
   - Возврат объекта с метаданными:
     - `valid`: `true`
     - `exportDate`: дата создания
     - `sitesCount`: количество объектов
     - `materialsCount`: количество позиций материалов и чеков
     - `checklistsCount`: количество пунктов технадзора
     - `hasTariffs`: булево (наличие сохраненных тарифов)
     - `appName`, `schemaVersion`.
   - При нарушении схемы: выброс понятного исключения с четким описанием проблемы на русском языке.
4. **Метод безопасного восстановления `restoreFromBackup(data)`**:
   - Валидация через `validateBackup(data)`.
   - Очистка и перезапись хранилищ IndexedDB с ожиданием реального завершения транзакций `tx.oncomplete` через `Promise.all`.
   - Восстановление тарифов мастера в `localStorage` (`liga_tariff_settings_v1`).
   - Возврат отчета об успешном восстановлении.

## 3. План верификации и автоматические тесты

### 3.1. Новый автотест Playwright: `tests/test_backup_restore.py`
1. **Тест экспорта**:
   - Клик по кнопке бэкапа, перехват скачиваемого файла `liga_backup_*.json`.
   - Проверка структуры JSON: наличие полей `appName`, `schemaVersion`, `sites`, `materials`, `checklists`, `tariffSettings`, `exportDate`.
2. **Тест строгости валидатора**:
   - Попытка передать некорректный JSON (поврежденный файл или чужой JSON без `sites`).
   - Проверка вывода сообщения об ошибке и запрета на замену базы.
3. **Тест полного цикла восстановления (End-to-End)**:
   - Создание нового тестового объекта (например, *«Вилла Самарканд Тест»*).
   - Экспорт бэкапа базы с этим объектом.
   - Изменение базы: создание второго объекта или редактирование существующего.
   - Загрузка сохраненного бэкапа, появление карточки метаданных, нажатие подтверждения.
   - Проверка восстановления: объект *«Вилла Самарканд Тест»* снова активен в селекторе и базе.
