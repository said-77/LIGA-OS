# Регламент для ИИ-агентов системы LIGA OS (AGENTS.md)

## 1. Миссия и назначение системы
**LIGA OS** (Операционная Система Инженерного Мастера) создается для ведущего инженера элитной сантехники и отопления в Ташкенте — **Улугбека Хакимова** («Лига Опытных Мастеров»).
Система переводит работу мастера с уровня «прораб на коленке» на уровень **«Швейцарский банк инженерных систем»**:
- Стандарт гидравлических испытаний **16 бар** в течение 24 часов (в 4 раза строже СНиП);
- Обязательный **Исполнительный Инженерный Паспорт** с фотофиксацией трасс и узлов ввода;
- Защита конфиденциальности мастера: **Режим показа клиенту** (Client View);
- **Автономность ядра**: ядро LIGA OS работает офлайн; голос, внешние ссылки и мессенджеры требуют сеть.

## 2. Профиль владельца и коммуникация
- Владелец проекта — практик, не программист.
- Любое общение, размышления, пояснения и отчеты ведутся **строго на русском языке**.
- Категорически запрещено перекладывать на владельца технические задачи: проверку портов, анализ логов DevTools, вычисление хэшей или правку исходного кода.
- Любой отчет владельцу должен завершаться обязательным итоговым блоком:
  `Что сделано / Что проверено / Файлы / Следующий шаг`.

## 3. Источники правды и границы архитектуры
- **Единственный канонический источник правды**: `HANDOFF_AND_SPEC_RU.md`.
- **Единый журнал решений и памяти**: `DECISION_JOURNAL.md`.
- **Запрет смешивания проектов**: файлы других проектов не должны использоваться или анализироваться.
- Архитектурный стек LIGA OS:
  - Чистый HTML5 / CSS3 (CSS Variables, Flexbox/Grid, Glassmorphism, Dark Titanium / Light Ceramic);
  - Vanilla JavaScript ES6+ (модульная архитектура классов, никаких тяжелых внешних фреймворков);
  - Локальная база данных: **IndexedDB** (хранилища `sites`, `materials`, `checklists`, `finances`, `passports`);
  - Локальный компрессор фотографий на Canvas (до 1600px WebP/JPEG);
  - Генератор официального паспорта А4 на чистом HTML/CSS для печати и сохранения в PDF (`window.print`);
  - Service Worker (`sw.js`) для кэширования ядра приложения (голос, внешние ссылки и мессенджеры требуют сеть).

## 4. Железные инженерные правила (Защита от симуляции)
1. **Против симуляции (Against Simulation):**
   - Запрещено оставлять заглушки `// TODO`, плейсхолдеры или имитацию логики.
   - Код должен быть полностью рабочим и отлаженным.
2. **Против угождения (Against Pleasing):**
   - Запрещено слепо соглашаться на архитектурно опасные решения. Если предложение вредит надежности или создает риск протечки данных — агент обязан аргументированно предложить Senior-решение.
3. **Безопасность Git:**
   - Категорически запрещено использовать `git add .` — только точечный коммит конкретных файлов.
   - Запрещено коммитить секреты, временные скриншоты или тестовые дампы.
4. **Совет трех экспертов перед работой:**
   - Архитектор: оценка чистоты связей, SOLID и отсутствия утечек данных.
   - Разработчик: лаконичный надежный стек без лишних зависимостей.
   - Инженер по качеству (QA): поиск граничных случаев, сбоев сети и утечек памяти.
5. **Хранение отчетов и порядок Рабочего стола:**
   - Канонические планы, отчеты и журналы хранятся в репозитории LIGA OS и фиксируются в Git.
   - Рабочий стол не используется для автоматических дубликатов. Выгружать туда отдельный документ разрешено только по прямой просьбе владельца.
